# 工作空间卡片刷新按钮设计

## 目标

在工作空间列表卡片右上角增加“刷新映射”按钮，让用户无需进入详情页即可重新读取该工作空间全部 Project 的文档入口、重建文档缓存和搜索索引，并立即看到最新异常统计。

## 交互设计

- 按钮始终显示在每张工作空间卡片的右上角，使用次要按钮样式，与左侧 Workspace 标签和标题形成左右布局。
- 点击后刷新该卡片对应的整个 Workspace，包括全部前端和后端 Project。
- 请求进行中按钮文案改为“刷新中…”，并禁用该按钮，避免同一工作空间重复提交。
- 刷新成功后，用接口返回的最新 Workspace 摘要替换当前卡片数据，更新项目、数据源、数据库、异常和授权统计。
- 请求失败时复用页面顶部错误提示展示后端错误，并重新读取该 Workspace 摘要；若刷新校验已经更新运行时错误状态，卡片异常数随之更新，恢复读取也失败时才保留原卡片数据。
- 不增加确认弹窗；刷新只重建可恢复的运行时缓存和派生搜索索引，不修改 Workspace 或 Project 配置。

## 数据流与安全边界

1. `WorkspaceDashboard` 调用新增的 `refreshWorkspace(workspaceId)` API 方法。
2. 前端请求 `POST /api/workspaces/{workspace_id}/refresh`。
3. 前端浏览器 API 策略将该精确路径加入安全 POST 白名单。
4. 后端 `BrowserReadOnlyMiddleware` 将同一路径加入安全 POST 白名单。
5. 现有 `WorkspaceManagementService.refresh_workspace` 完成全 Workspace 刷新并返回最新 `WorkspaceSummary`。
6. 前端只替换对应 ID 的卡片数据，不重新加载整页。

刷新接口不会加入宽泛路径规则；Workspace 创建、编辑、删除和其他管理命令仍由浏览器只读策略阻止。

## 错误处理

- 网络错误或非 2xx 响应：读取该 Workspace 最新摘要后解除按钮禁用状态，在页面顶部展示现有请求错误信息；恢复读取失败时保留原卡片数据。
- 刷新完成但部分 Project 仍异常：接口正常返回，卡片的“异常”数字展示最新结果，用户可进入工作空间查看具体错误。
- 多张卡片并存时，仅禁用正在刷新的卡片按钮；其他卡片仍可独立操作，各 Workspace 的错误状态按 ID 隔离。

## 测试与验证

- 前端策略单元测试：浏览器允许精确的 Workspace 刷新 POST，仍拒绝其他配置和执行命令。
- 后端中间件测试：带浏览器 Origin 的刷新 POST 可通过，其他配置写请求仍返回 405。
- 前端 API/交互测试：验证刷新方法使用正确路径和 POST；若现有组件测试基础不足，至少以策略测试、TypeScript/lint 和浏览器手动验证覆盖按钮状态与卡片更新。
- Docker Compose 中运行前端测试、lint、build 和相关后端测试。
- 在本机页面验证按钮位置、加载态、刷新后异常数变化及窄屏布局。
