# Context Router 接口日志采集扩展

版本 0.3.18 使用 Chrome `webRequest` 网络事件保存 Fetch/XHR 请求条目，
不依赖页面替换 fetch/XHR。以下来源映射到各自环境：

### 0.3.18：司机 H5 会话监听

- TEST、UAT、PRE 的 `/hep-h5` 登录页通过 `/rest/facade/api/app/auth/login` 与
  `getLoginUserInfo` 确认手机号；已登录页面也可从 localStorage 的 `token` 和
  `userInfo.mobile` 恢复身份，但必须与成功请求的 `_sid` 一致。不采集密码、短信码或完整用户资料。
- 每个环境为 `c12-mtp` 单独登记“司机端”地址，基址为该环境网关的 `/rest/mtp`。
  后端仅将同环境、同源、`x-system-code: app` 的 H5 Facade 成功请求映射到这个地址；
  不写入“运营端”或“门户端”身份。未登记地址或身份无法确认时不猜测账号。
- 后端变更需按 Native Stack 规范重启；在 `chrome://extensions` 重新加载扩展，
  然后刷新已登录的司机 H5 页面并触发一次业务请求。旧请求不能补出未采集的会话 Header。

### 0.3.17：运营端持续同步登录态

- 运营端 `/op`、`/pzh-mtp-ui`、`/pzh-portal-admin-ui` 页面支持读取当前 Vue/Pinia
  `user` 状态中的 `userName`。页面 sessionStorage、用户状态 token 与成功请求的 `_sid`
  必须一致；只返回账号，不返回完整用户资料或凭据。
- 登录超过五分钟、刷新页面或扩展重载后，成功业务请求仍可触发 session 同步。
  运营端按账号同步空角色身份，不把权限角色列表另建成登录身份；后端已有身份更新凭据，
  不存在则新增，账号匹配忽略大小写并保留已有记录的账号拼写。
- 默认同步只作用于实际请求对应的服务与运营端地址。未登录、页面身份未就绪、凭据不一致
  或调试器不可用时不猜测身份；原登录确认路径继续作为补充。
- 在 `chrome://extensions` 重新加载本扩展，再刷新已登录的运营端页面并触发查询。
  此次不修改后端，无需重启 Native Stack。

### 各环境运营端共享登录（后端同步组）

攀枝花 Workspace 按环境分别配置共享登录组：UAT 为 `http://192.168.0.222:28080`，
TEST 为 `http://192.168.0.222:18080`，PRE 为 `http://223.87.29.28:30080`，
LOCAL 为 `localhost` / `127.0.0.1` 的 3000、3001 前端入口，转发到本机 18880 网关。
扩展确认空角色运营端账号并同步任一组内服务后，后端在同一事务中更新
`c12-mtp`、`c12-sys`、`c12-portal` 三个服务的“运营端”身份。已存在则更新请求头，
不存在则新增；账号大小写匹配沿用已有规则。保留实际观察到的 `_sid` 和
`x-system-code`，不按服务路径猜测系统码。
此规则只匹配该 Workspace、所选环境对应的网关来源和明确的运营端身份，门户端、
管理端及其他环境继续独立同步。规则位于 `services/browser_auth.py` 的
`SHARED_LOGIN_GROUPS`，变更后按仓库规范重启 Native Stack；扩展 0.3.17 无需再次升级。
LOCAL 需登记 MTP、SYS、Portal 三个名为“运营端”的地址，基址分别为
`http://127.0.0.1:18880/rest/mtp`、`/rest/sys`、`/rest/portal`；旧“本地网关”配置保留。

### 0.3.16：采集背压与登录态有界重试

- 后端采集最多同时执行 2 个导入，其余立即返回繁忙，扩展保留待传记录并按原退避重试。
- 每条采集独立提交；锁等待上限 1.5 秒、单条 SQL 上限 5 秒，连接超时 5 秒。
  路径匹配缓存有大小上限，固定路径不再编译正则。SQL 超时不是整批 CPU 执行总时限。
- 登录态仅在内存中排队，最多 32 项、5 分钟；失败按 5/10/20/30 秒退避，最多尝试 5 次。
  相同目标及凭证成功后 5 分钟内去重，新凭证替换同身份待重试旧凭证。
  只有 `status=synced` 才算成功；凭证不进入磁盘日志或持久采集队列。
- 扩展后台休眠/重载会丢失内存中的登录重试，恢复后需刷新业务页产生新请求。
  后端更新需重启 Native Stack；扩展需在 `chrome://extensions` 重新加载。

鉴权同步仅保存已识别账号：扩展跳过未确认身份，后端对缺少账号或
`browser-session:` 前缀返回 `skipped/verified_account_required`，不连接数据库写入身份。
这不影响普通脱敏接口日志采集。管理端当前仅在登录确认窗口内识别账号，窗口过期后
不再同步无法确认的凭证；不会退回匿名身份。

门户身份支持配置 `pageIdentity`：仅从同来源、匹配路径的当前标签页读取指定存储键，
校验存储令牌与实际请求凭证一致后，提取白名单账号与当前角色字段。支持双层 JSON 存储；
不返回完整用户资料、密码或令牌。选择身份后及刷新页面后可随成功请求同步账号和角色，
不再仅依赖登录后五分钟的临时关联。服务映射仍以实际观察到的请求为准，不跨服务复制凭证。

- `http://localhost:3000/*`、`http://127.0.0.1:3000/*`，以及两个地址的 3001 端口 → `local`
- `http://localhost:2077/*`、`http://127.0.0.1:2077/*` → `local`；独立管理端登录以 `/auth/api/system/login/login` 和后续 `getLoginUserInfo` 关联真实账号，仅匹配名称为“管理端”的已登记转发地址。不会复用 18880 的运营/门户网关；缺少管理服务登记时须先补齐，不能猜测绑定。
- `http://192.168.0.222:18080/*` → `test`
- `http://223.87.29.28:30080/*` → `pre`
- `http://192.168.0.222:28080/*` → `uat`

Fetch/XHR 中路径以 `/sse/connect` 结尾的 SSE 长连接不采集；其他普通接口以及
`/sse/disconnect` 等控制请求仍按正常 Fetch/XHR 处理。

请求发出时先写浏览器本地存储，完成和响应补全使用同一 capture_id 的递增 revision。
上传不阻塞本地队列；只有服务端逐条确认入库后才标记已发送。网络超时后保留记录，
按 5 / 10 / 20 / 30 秒退避重试，后续间隔上限为 30 秒；字段不合法的单条记录隔离保留，
可点击“重试待传”。后端匹配接口后，
`operation_kind=read` 的查询接口按 Workspace、环境、接口和北京时间自然日只保留一个样本；
优先保留成功响应，并累计观察次数与成功次数。写入、破坏性和未分类接口仍逐次保存。
已确认或当日去重的记录本地保留五分钟用于响应补全，未确认记录不自动删除。
队列上限 100 MiB，容量不足明确显示失败次数，不静默挤掉旧请求。普通请求日志不保存请求头，
请求/响应体在浏览器端和服务端分别脱敏、限长；大响应保存截断预览。

后端先保存脱敏原始观察，再匹配接口目录。未收录、多义匹配、地址缺失等记录进入
“待匹配”，不会被丢弃；补齐接口目录或配置后可点击“重新匹配”。已匹配记录继续出现在
Context Router 原有接口日志中，全部原始记录可在扩展弹窗查看。

## 静态资源过滤（0.3.15）

Fetch/XHR 也可能用于预加载前端资源。三个采集通道统一排除 assets/static/_next/static
目录下的常见 CSS、JS、字体和图片资源，以及已知 `/pzh-mtp-ui` 页面入口。
仅路径满足静态目录和后缀双条件才过滤；rest/api/*-api 路由优先保留，避免误排除业务下载。
未知业务路径继续保存原始记录并进入待匹配，不按相似接口名强行关联。
历史已入库记录和待上传队列不删除；本次只减少重新加载后新产生的静态资源记录。
重新加载扩展、刷新业务页面，已打开的 DevTools 关闭后重开；此次无需重启后端。

## 响应状态与安全入库（0.3.14，继续适用）

此版本需要后端同步升级并在 `chrome://extensions` 重新加载本扩展。
重新打开业务页面；若 DevTools 已打开，也应关闭后重开以加载新响应采集代码。

- 状态由后端统一计算，扩展不保存中文标签。HTTP 200 的业务失败不计为成功样本，
  因此不会阻止后续真实成功响应成为每日代表样本。
- 缺正文、截断、非 JSON 文本显示“已请求”，不误判“无数据/有数据”；真实空 JSON 数据
  仍按合同显示无数据。请求体截断不再等同于响应截断。
- Debugger 与 DevTools 两个响应通道都按 MIME 与内容识别二进制，仅保存有界元数据。
  base64 JSON 正常解析；大文本只保存截断标记；二进制不会解码成原文入库。
  observed_bytes 是扩展观察到的内容字节数；数据库 response_bytes 仍是保存摘要的序列化字节数，
  不应混同网络压缩后的传输字节数。
- 后端兼容旧扩展的 NUL 内容，防止原始 JSONB 保存失败；missing 标记随同 capture_id 的
  新 revision 补全响应后消失。队列、退避、ACK、登录同步、每日去重 SQL 结构不变。
- 不自动重发请求、不回填缺失正文、不重写历史累计成功数。历史每日样本若已按旧逻辑被选中，
  不保证会被新采集覆盖；需要另行审计，不凭空修正旧证据。

## 批量上传调度说明（0.3.13，继续适用）

只调整采集扩展，不改变后端接口、数据库和接口匹配逻辑。已安装 0.3.12 且后端正常的用户，
在 `chrome://extensions` 重新加载本扩展即可启用这次更新，无需重启 Native Backend。

- 同一环境待上传达到 10 条立即调度；不足 10 条时，以最早一条未确认记录的等待时间为准，
  等待 5 秒后上传。新请求、完成事件或响应补全不会反复推迟这个期限。
- 每批最多 10 条，完整 JSON 请求体最多 1 MiB（UTF-8 字节数）；积压分批串行发送，环境不混装。
  单条超限时明确标记失败并保留本地，不阻塞其他有效记录。
- 上传失败或响应未确认全部记录时，保留未确认部分并按环境退避；新增采集、数量阈值和
  周期检查不会绕过退避。成功后重置该环境退避；一个环境失败不会暂停其他环境。
- 等待起点和重试截止时间保存到浏览器本地，扩展后台重启后继续沿用。后台休眠会延迟定时器，
  原有 30 秒周期唤醒和浏览器启动检查负责兜底，5 秒不是浏览器休眠时的实时保证。
- “重试待传”可跳过数量和等待时间条件，但仍遵守失败退避。登录身份和 Session 同步继续走
  独立即时通道，不等待日志批次，凭证不进入本地采集队列。

参数集中在 `service-worker.js` 的 `CONFIG.upload`。这只是减少零碎上传，不等同于后端批量 SQL，
也不解决后端长事务或残留进程问题。本地 100 MiB 上限和原有逐条 ACK/revision 规则保持不变。

## 按环境同步登录 Header（0.3.0）

`onSendHeaders` 观察 `_sid`、`Authorization`（浏览器可见时）和 `X-System-Code`；
HTTP 2xx 请求完成后通过独立 `/browser-captures/auth` 入口保存到已有转发身份表。
原始凭证不进入扩展持久日志队列、接口日志或 MCP 返回。认证接口与业务转发地址可使用
不同服务前缀：认证接口只确认账号，同标签页、同环境随后发出的真实业务请求才用于匹配
转发地址，后端地址边界不会因此放宽。现有本机身份表的
`request_header` 存储模式仍为明文，未引入加密。HTTP 2xx 仅代表候选凭证，
不等于验证业务登录成功；后续接口返回 401 时仍需浏览器重新登录并产生新请求。

服务端按 Workspace、环境、实际 origin 和网关路径前缀校验；同源地址若跨环境登记，
拒绝同步。仅 LOCAL 允许 localhost/127.0.0.1 的 3000/3001 映射到 18880；
TEST/UAT 必须严格同源。不接受 allow_origin_mismatch。
认证与业务路径不同时，服务端只允许用格式受限的 `X-System-Code` 精确匹配服务名末段
（例如 `mtp` 匹配 `c12-mtp`），并仍要求 Workspace、环境和 origin 全部一致。
相同 Header 的多标签页共用一个匿名浏览器会话身份；不同凭证不会覆盖彼此，
默认不推断真实账号名或角色。配置登录身份规则后，扩展只从登录请求临时提取账号字段，
丢弃密码、验证码和密钥；随后仅在同一环境、同一标签页、五分钟内的已配置当前用户接口
携带凭证且返回 HTTP 2xx 时，才把匿名身份原地提升为账号身份。规则只描述路径、方法和
账号字段，并可声明本次登录对应的转发地址名称；例如门户登录只绑定“门户端”，
运营端登录只绑定“运营端”，避免同一服务基址登记多个调用入口时把凭证写入错误入口。
地址名称只是登录规则的配置数据，后端仍按实际来源、环境、基址和精确名称共同校验，
匹配实现不包含 Workspace 业务判断。重新登录产生不同凭证或浏览器重启后可能出现多个身份，
MCP 仍沿用原有明确选择规则，必要时选择身份或删除失效的匿名身份。
存在待确认登录账号时，扩展不会先发布临时匿名身份；只有当前用户确认请求成功后才直接同步
命名账号，避免同一次登录同时留下命名账号和 `browser-session:*`。
服务端短暂离线后，下次成功的业务请求会再次尝试同步；不持久化原始凭证重试队列。

升级后重启 Native Backend，并在 chrome://extensions 重新加载本扩展，再打开对应
环境的业务页面进行查询。已有采集日志不能还原未采集过的 Header。

## 安装

1. 确认 Context Router 已启动并完成数据库迁移。
2. Chrome 打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本目录。
4. 停用暴力猴/脚本猫中的旧“Agent Context 接口请求录制器”，刷新已有业务页面以移除旧拦截器。
5. 正常操作业务页面，点击扩展图标查看“已采集 / 已入库 / 待传更新 / 失败”及服务端实际记录。

Chrome debugger 只负责补充响应体，并自动关联子 target。打开 DevTools 后，
`devtools.network` 桥接补充响应；浏览器网络事件始终独立记录请求和状态码。桥接刚连接、
调试器切换、响应缓存回收或并发同 URL 请求无法可靠关联时，记录会标明“缺响应正文”，
不猜测响应属于哪次请求。关闭 DevTools 后自动尝试恢复 debugger。

“监听”仅表示监听器已注册，不代表所有条目已入库；请看弹窗中的实际服务端记录。
浏览器崩溃前尚未来得及本地写入的事件、非 Fetch/XHR、白名单以外地址不保证覆盖。
进行中的请求在标签页关闭或十分钟未结束后标记为未完整结束，保留已获得信息。

首次升级要求 backend migration `20260920_0094`，随后按项目规范重启 Native Stack。
旧扩展的 pendingInterfaceCaptures 队列会自动迁移，已有接口日志不会删除。
